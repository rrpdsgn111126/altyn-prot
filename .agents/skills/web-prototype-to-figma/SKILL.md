# Перенос веб-прототипа в Figma

## Источники

- Веб-прототип определяет тексты, данные, сценарии, порядок блоков и состояния. Проходи сценарии через Playwright с Chromium.
- Оригинальные компоненты целевой дизайн-системы определяют внешний вид, размеры, варианты и свойства. Проверяй опубликованную библиотеку и разрешённые локальные компоненты целевого файла.
- Целевой файл и его референсы определяют композицию экранов. Для Altyn используй Altyn.Base, подтверждённые композиции Altyn App и актуальный `docs/mobile-screen-layout.md`.

## 1. Разметка и согласование

1. Перечисли экраны и состояния, включая заполненные формы, ошибки, загрузку и модалки. Для визуально одинаковых состояний укажи общий кадр.
2. Используй существующий `figma-mapping.json` или создай его рядом с прототипом. Для каждого элемента запиши экран, состояние, роль и стабильный ID. В `htmlSource` укажи путь или URL и селектор. В `figmaTarget` укажи файл, ссылку, ID или ключ компонента, вариант, свойства и основание соответствия. Для составных элементов перечисли нужные узлы.
3. Повторно используй записи `verified`. Для `partial` проверь только недостающие свойства. Для `unmapped` определи, подходит ли штатный слот, композиция, Auto Layout-контейнер или текстовый слой. Если подходящий контрол не подтверждён, запиши `Custom / Unmapped`, причину и конкретный вопрос к пользователю.
4. Покажи скриншоты с номерами рядом с элементами. В легенде укажи найденный компонент, вариант, статус и ссылку. Собери комментарии пользователя по спорным элементам и внеси их в mapping. Сохрани mapping в Git проекта, если доступ и задача это предусматривают. В Altyn добавляй новые подтверждённые правила в `docs/mobile-screen-layout.md` без дублей.
5. Если запрошена только разметка, заверши этап после её передачи. Если сборка уже разрешена, продолжай по подтверждённым соответствиям и уточняй только решения, блокирующие конкретные кадры.

## 2. Сборка

1. Определи целевые файл, страницу и секцию. Загрузи инструкции для Figma MCP и проверь доступ к целевому файлу и компонентам.
2. Собери один репрезентативный кадр. Проверь источник связанных instances, варианты, свойства, вложенные слоты и Auto Layout. После проверки перенеси остальные уникальные состояния.
3. Сохраняй исходные тексты и данные. Используй штатные вложенные свойства, иконки, стили и переменные. В Altyn, например, флаг страны в `Input.mobile` подключай через правый `Addons` и `Services icons / Flag`.
4. Сохраняй связи instances и существующие мастера. Используй редактируемые кадры Figma. Оставляй HTML-импорт и скриншоты в роли справочных материалов.
5. При точечных исправлениях сохраняй идентичность существующих кадров и правки пользователя. Удалённые кадры восстанавливай только по прямому запросу. Переходы Figma Prototype добавляй по запросу.

## 3. Проверка и передача

Сверь кадры с исходным перечнем состояний и текстами. Через Figma MCP проверь источники instances, варианты, свойства, вложенность и Auto Layout. Визуально проверь ключевые экраны, длинные значения, ошибки и модалки.

Передай ссылку на целевую секцию, число созданных и обновлённых кадров, число проверенных связанных instances, соответствия для одинаковых состояний, список `Custom / Unmapped` и результаты проверок. При ограниченном доступе передай проверенную разметку и укажи, какие кадры или проверки остались откры.
