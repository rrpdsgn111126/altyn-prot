# Altyn App — структура мобильного экрана и система отступов

> Статус: рабочая спецификация для HTML-прототипов и последующей разметки компонентами Figma.  
> Дата фиксации: 2026-11-11.  
> Источник: [Altyn App / Processing](https://www.figma.com/design/n9eR5MzhUA8BpvjO9ciYgi/Altyn-App?node-id=17511-5197).  
> Приоритет: явно зафиксированные в этом документе правила выше значений в старых макетах. Не распространять размеры отдельного сценария на все экраны без проверки.

## 1. Каркас экрана

Базовая последовательность сверху вниз:

1. **System Status Bar** — системная строка состояния, отдельная от содержимого экрана.
2. **Top Navbar** — навигация приложения: возврат, заголовок, при необходимости действие справа.
3. **Дополнительная верхняя область (опционально)** — например, баланс.
4. **Main Content** — основная область содержимого, с горизонтальными и вертикальными полями, прокруткой при переполнении.
5. **Нижний блок действий (при наличии)** — кнопка / ссылка / подсказки. Может находиться внутри области контента или закрепляться над системной навигацией, в зависимости от сценария.
6. **System Bottom Navigation / Safe Area** — отдельная нижняя системная область, не часть контента.

### Измеренный пример: экран 375 × 812 px

| Уровень | Положение Y | Высота | Условие |
| --- | ---: | ---: | --- |
| System Status Bar | 0–40 | **40 px** | Измерено в Figma |
| Top Navbar | 40–94 | **54 px** | Измерено в Figma |
| Main Content | 94–764 | **670 px** | Высота для данного примера, не фиксированный токен |
| Bottom System Navigation | 764–812 | **48 px** | Измерено в Figma |

Пример: [Вывод СБП, новый макет](https://www.figma.com/design/n9eR5MzhUA8BpvjO9ciYgi/Altyn-App?node-id=18248-129059).

**Вариант с балансом:** в макетах высотой 934 px встречается верхняя область баланса высотой **72 px** между navbar и Main Content. Пример: [Пополнение, банковские реквизиты NEW](https://www.figma.com/design/n9eR5MzhUA8BpvjO9ciYgi/Altyn-App?node-id=18443-135518): Status 40, Navbar 54, Balance 72, Main Content 720, Bottom Navigation 48.

**Важно:** 40/54/48 — размеры конкретных Figma-макетов, полезные при воспроизведении HTML-прототипа под эту базу. В нативной реализации системные зоны должны учитывать реальные safe-area и системные размеры устройства. Не хардкодить высоту Main Content.

## 2. Горизонтальная сетка — обязательное правило

- **Левый внешний отступ содержимого: 16 px.**
- **Правый внешний отступ содержимого: 16 px.**
- **24 px с боков — устаревшее решение: не использовать для новых экранов.**
- При ширине экрана **375 px** ширина контентного контейнера: **375 − 16 − 16 = 343 px**.
- Вложенный список / карточка шириной 343 px может иметь **собственные внутренние горизонтальные поля 16 px**, в таком случае строка внутри него имеет ширину **311 px**. Это не замена внешним полям экрана.
- Внутренние 24 px внутри отдельного компонента (например, текстовые поля кнопки) **не равны** внешним полям страницы: их не следует автоматически заменять.

### Пример вложенности

~~~text
Экран 375
├── внешнее поле 16
├── Main Content / группа 343
│   ├── внутреннее поле группы 16 (если предусмотрено компонентом)
│   └── list.mobile / содержимое 311
└── внешнее поле 16
~~~

**Приоритет при расхождении:** если экран содержит внешний padding-left/right = 24 px или внешний контейнер шириной 327 px при ширине экрана 375 px, привести внешнюю сетку к 16 px / 343 px. В старых слоях такие значения встречаются, но не должны считаться нормативными.

## 3. Вертикальные интервалы — обязательные правила

| Контекст | Интервал | Статус |
| --- | ---: | --- |
| Между последовательными инпутами в форме | **12 px** | Нормативное правило |
| Между отдельными контейнерами / группами списков | **12 px** | Нормативное правило |
| Между соседними строками **внутри одной** цельной группы списка | **0 px** | Измерено для примера list.mobile; строки не раздвигать искусственно |
| Между разделами формы и следующим функциональным блоком | **По контексту: часто 24 px** | Измерено, не глобальное правило |
| Между вспомогательной ссылкой и основной кнопкой | **16 px** | Измерено в отдельных сценариях |

### Чем отличаются группа и строка списка

В [сценарии банковских реквизитов NEW](https://www.figma.com/design/n9eR5MzhUA8BpvjO9ciYgi/Altyn-App?node-id=18443-135518):

- Первый контейнер списка содержит последовательные строки list.mobile с шагом, равным высоте строк (например, 54 px): **дополнительный gap = 0 px**.
- Между первым контейнером списка и следующим отдельным контейнером — **12 px**.
- Содержимое отдельных строк списка имеет собственные внутренние поля; не путать их с расстояниями между группами.

### Инпуты

В [выводе СБП (new)](https://www.figma.com/design/n9eR5MzhUA8BpvjO9ciYgi/Altyn-App?node-id=18248-129059), [международной карте](https://www.figma.com/design/n9eR5MzhUA8BpvjO9ciYgi/Altyn-App?node-id=17511-7162) и [банковских реквизитах](https://www.figma.com/design/n9eR5MzhUA8BpvjO9ciYgi/Altyn-App?node-id=17511-7316) вложенные контейнеры Inputs используют **itemSpacing = 12 px**. Промежуточный элемент (например, конверсионная стрелка / divider) считается элементом стека: 12 px до и 12 px после, если он участвует в обычном вертикальном потоке.

Встречающееся в отдельных более старых экранах **16 px между инпутами не использовать как новый стандарт**, поскольку нормативное значение — 12 px.

## 4. Остальные измеренные вертикальные значения

Эти интервалы наблюдаются в конкретных слоях Figma и **не являются универсальными отступами между любыми элементами**.

| Значение | Где встречается | Как применять |
| --- | --- | --- |
| **0 px** | Между последовательными крупными фреймами без дополнительного разделителя; между строками внутри одной группы list.mobile; внутри пары label/value в некоторых инпутах | Только там, где блоки конструктивно смыкаются |
| **2 px** | Мелкие подписи внутри компонента баланса | Внутри соответствующего компонента, не на уровне страницы |
| **4 px** | Внутри переключателя банка (ToggleBank), между элементами подписи / внутренней компоновки | Локальный отступ компонента |
| **8 px** | Внутри некоторых элементов list.mobile; между иконкой и текстом/внутри вспомогательных контролов | Локальный компонентный интервал |
| **10 px** | Между несколькими ссылками во вспомогательном блоке; также как внутренний itemSpacing отдельных контейнеров | Только после проверки реальных координат; не применять как общий отступ экрана |
| **12 px** | Стек инпутов; независимые группы списков; input → вспомогательный текст; соседние элементы содержимого форм | **Основной нормативный шаг на уровне формы / групп** |
| **16 px** | Верхние/нижние поля некоторых секций; между ссылкой и кнопкой в отдельных сценариях | Разделение или внутренний padding, когда подтверждено структурой |
| **24 px** | Отделение блока формы от блока действий; верхнее поле формы в части старых/других сценариев | Допустимо **по вертикали**; запрет 24 px касается **внешних боковых** полей |

Число 10 в свойстве Auto Layout корневых экранов не всегда означает реальный видимый зазор: например, Status, Navbar, Content и нижняя системная область в типовых кадрах геометрически примыкают друг к другу без разрыва. Для измерения используются фактические координаты и вложенность, а не только значение itemSpacing.

## 5. Вертикальные поля контента и действия

В разных сценариях встречаются **разные контекстные значения**, поэтому нельзя вводить одно обязательное значение для верхнего или нижнего поля всех экранов только на основании этой страницы Figma:

- **Верхнее поле 16 px** — подтверждено в более новых формах (например, после панели баланса в банковских реквизитах NEW и мультитрансфере).
- **Верхнее поле 24 px** — присутствует у ряда форм, открывающихся непосредственно под Navbar (например, вывод СБП, международная карта). Это вертикальный отступ, а не устаревшее боковое поле.
- **Нижнее поле 16 px** — часто применяется внутри нижней области действий / завершения содержимого непосредственно перед системной нижней областью.
- **Нижнее поле 12 px или 0 px** может встречаться у внутренних подблоков, если за ними следует другой контейнер; не трактовать такое значение как поле всего экрана.
- **Кнопка действия часто имеет высоту 54 px**. Для кнопки шириной 343 px сохраняются внешние поля 16 px экрана, а не внутренние поля самой кнопки.
- **Исключение для действий в модалках:** `Button.mobile` используется в размере **M** (у Primary/M высота **44 px**). Высоту кнопок основного экрана (часто 54 px) нельзя автоматически переносить в Bottom Sheet; подробности — раздел 10.
- Нижняя кнопка должна оставаться **выше** System Bottom Navigation; в прокручиваемых формах её фиксация или прокрутка определяется конкретным UX-сценарием, а не видом нарисованного кадра.

## 6. Рекомендуемый каркас HTML-прототипов

Семантическая структура:

~~~text
MobileScreen (flex column; min-height: viewport)
├── SystemStatusBar           [Figma baseline: height 40]
├── AppNavbar                 [Figma baseline: height 54]
├── OptionalTopContext        [например, balance: height 72]
├── MainContent               [flex: 1; scrollable]
│   ├── ContentSection        [padding-inline: 16; top/bottom by scenario]
│   │   ├── InputStack        [gap: 12]
│   │   └── ListGroupStack    [gap: 12]
│   │       └── ListGroup     [rows: gap 0 when contiguous]
│   └── OptionalActionArea    [padding-inline: 16; bottom often 16]
└── SystemBottomArea          [Figma baseline: height 48]
~~~

Пример токенов реализации:

~~~css
:root {
  --screen-gutter: 16px;
  --input-stack-gap: 12px;
  --list-group-gap: 12px;
  --list-row-gap: 0px;
  --section-to-action-gap: 24px; /* только там, где это предусмотрено сценарием */
}

.main-content {
  flex: 1 1 auto;
  min-height: 0;
  overflow-y: auto;
}

.content-section,
.action-area {
  padding-inline: var(--screen-gutter);
}

.input-stack,
.list-group-stack {
  display: flex;
  flex-direction: column;
  gap: 12px;
}

.list-group {
  display: flex;
  flex-direction: column;
  gap: var(--list-row-gap);
}
~~~

Верхний/нижний padding самого ContentSection задаётся осознанно в зависимости от структуры конкретного экрана (см. раздел 5), а не берётся из случайного старого макета.

## 7. Проверка новых прототипов

1. System Status Bar, Navbar, Main Content и нижняя системная область разделены на самостоятельные зоны.
2. Для ширины экрана 375 px вся основная контентная сетка начинается на X = 16 px и заканчивается на X = 359 px; полная ширина контейнера = 343 px.
3. Нет **внешних** боковых полей 24 px, даже если они встречаются в скопированном Figma-экране.
4. Между соседними инпутами / элементами одного стека выдержан gap = 12 px.
5. Между **отдельными** контейнерами списка выдержан gap = 12 px; строки одной цельной группы не разнесены дополнительными 12 px.
6. Вертикальные 16/24 px используются только по назначению конкретного блока; нельзя механически заменять любой 24 на 16.
7. Кнопки не перекрывают системную нижнюю область; длинная форма прокручивается без потери доступа к управлению.
8. Внутренние отступы компонентов (list.mobile, Input.mobile, Button.mobile, navbar и т. п.) не подменяют внешнюю сетку экрана.
9. При расхождении старого кадра Figma с этой спецификацией применять нормативные значения и фиксировать исключение, если оно обосновано UX-сценарием.
10. У `Input.mobile` label находится **внутри** общей рамки с вводимым значением, а не отдельным текстом над инпутом (раздел 9).
11. Для Bottom Sheet проверены фон Secondary по умолчанию, белые контейнеры списков, кнопки M, 16 px по бокам, handle, прокрутка и safe-area (раздел 10).
12. Селектор открывает Bottom Sheet; проверены поиск по необходимости, иконки справа, обновление выбранного значения и сохранение при отмене (раздел 11).

Интервалы и размеры сняты с иерархии слоёв, Auto Layout и фактических координат репрезентативных экранов страницы Processing (включая пополнение и вывод). Устаревшие сценарии с пометкой OLD не принимались как нормативные. Значения из отдельных вложенных компонентов отнесены к локальным интервалам, а не объявлены общими токенами. **Это спецификация каркаса и отступов, не полный каталог свойств всех компонентов и не полная спецификация всех страниц Figma.**


## 9. Input.mobile — компоновка label и состояний

Нормативный компонент: [Altyn.Base / Input.mobile](https://www.figma.com/design/eZfU7lRRxu3GYH2S2KRgMy/?node-id=77-12680). Это **поле с label внутри общей рамки**, а не классическая форма с отдельной подписью над input.

| Состояние | Компоновка внутри рамки |
| --- | --- |
| **Enable, пустое поле** — [2152:12365](https://www.figma.com/design/eZfU7lRRxu3GYH2S2KRgMy/?node-id=2152-12365) | Один label **16/24 px**, вертикально по центру поля; над рамкой никакого label |
| **Enable + placeholder** — [2190:18818](https://www.figma.com/design/eZfU7lRRxu3GYH2S2KRgMy/?node-id=2190-18818) | Label **12/16 px** у верхней части поля; ниже placeholder **16/24 px**, даже без фокуса |
| **Filled** — [2014:9857](https://www.figma.com/design/eZfU7lRRxu3GYH2S2KRgMy/?node-id=2014-9857) | Маленький label **12/16 px** сверху и введённое значение **16/24 px** под ним; оба **внутри** рамки |
| **Focus / Active** | Label остаётся внутри; при вводе/фокусе применяется соответствующий вариант состояния и активная рамка |
| **Invalid** | Внутренняя компоновка label/value сохраняется; рамка ошибки и подсказка ошибки используют собственные цвета |
| **Disabled** | Сохраняется базовая геометрия поля; ввод недоступен |

Подтверждённые параметры поля: **54 px** высота, **12 px** радиус, Enable — рамка `#E9ECF0`, Focus — `#FFD119`, Invalid — рамка `#DD4014` и фон `#FFF4F8`. Текст и значение не должны выходить за границы одного контейнера поля. В HTML общая рамка принадлежит контейнеру, а label и элемент ввода находятся **внутри него**.

На уровне **вертикального стека формы** расстояние между соседними компонентами Input.mobile остаётся **12 px** (раздел 3). Это не зазор между label и value внутри поля.

## 10. Modal / Bottom Sheet — фон, слои, списки и кнопки

Базовый референс: [Altyn App / «Документы для банка», modal 18443:138108](https://www.figma.com/design/n9eR5MzhUA8BpvjO9ciYgi/?node-id=18443-138108).

**Правило по умолчанию:** нижняя модалка использует **Secondary фон**, а вложенный **список — отдельный белый (Primary) контейнер**. Не заливать всю модалку белым только потому, что внутри неё белый список.

| Элемент | Значение | Область действия |
| --- | --- | --- |
| Фон самой модалки | `bg/neutral/secondary` = **`#F6F7F8`** | Стандартный фон Bottom Sheet |
| Исключение: фон модалки Primary | **`#FFFFFF`** | Когда это явно задано в исходном сценарии; пример [17511:164381](https://www.figma.com/design/n9eR5MzhUA8BpvjO9ciYgi/?node-id=17511-164381) |
| Верхние углы модалки | **12 px** | Для проверенных модальных фреймов |
| Вертикальная ручка (handle) | **56 × 4 px** | По центру, в верхней зоне высотой 20 px |
| Горизонтальные поля содержимого | **16 px** | Включая заголовок, внутренние блоки и область кнопок |
| Заголовок | **18 px / 27 px, Semi Bold** | В референсе «Документы для банка»; другие варианты заголовка сверять отдельно |
| Контейнер списка в модалке | `bg/neutral/primary` = **`#FFFFFF`** | Самостоятельный блок, лежащий на фоне Secondary |
| Радиус списка документов | **16 px** | Подтверждён для modal `18443:138108`; **не распространять автоматически** на все типы списков |
| Внутренние поля списка | **16 px** слева и справа | При ширине модалки 375 px: список шириной 343 px, строка внутри — 311 px |
| Строка списка | `list.mobile`, **54 px**, разделитель `#E9ECF0` | Строки одной группы следуют без дополнительного gap |
| Отступ содержимое → блок действий | **24 px сверху** | В `Buttons-vert` проверенной модалки |
| Action-кнопки модалки | **`Button.mobile`, `Size=M`** | Для обычных действий в Bottom Sheet; **Primary/M = 44 px** |
| Нижняя системная область | **48 px** в проверенном Figma-кадре | Отдельная область внутри нижней части экрана; учитывать safe-area устройства |

**Важно о кнопках:** у разных `Type` размер `M` не обязательно означает одинаковую измеренную высоту. Фиксированные **44 px** подтверждены для **Primary/M** в приведённом референсе. Не подменять `Size=M` на `L` из-за того, что на основных экранах часто встречаются кнопки высотой 54 px.

**Правило о списках:** 16 px — радиус **контейнера документов** из этого примера. Поисковая панель выбора страны в текущем кодовом каталоге использует **12 px**, то есть не нужно приводить *все* белые списки модалок к радиусу 16 px. Сохранить вариант исходного компонента конкретного сценария.

**Высота и прокрутка:** Bottom Sheet закреплён внизу, не должен необоснованно перекрывать верхнюю системную область; при длинном содержимом прокручивается внутренняя область, а действия и нижняя системная зона должны оставаться доступны. Для прототипов под базовый Figma-экран использовать ориентир Status Bar = 40 px, System Bottom Area = 48 px; на настоящем устройстве учитывать реальные safe-area.

**UX-тексты:** заголовок модалки называет действие или содержание и не дублирует бессмысленно Navbar. Для заголовков, кнопок, пустых состояний и ошибок соблюдать [ux-writing-guidelines.md](./ux-writing-guidelines.md).

## 11. Выбор из списка — селектор с Bottom Sheet

Примеры в Altyn App:
- [17511:236855 — выбор страны с поиском](https://www.figma.com/design/n9eR5MzhUA8BpvjO9ciYgi/?node-id=17511-236855)
- [17511:164381 — выбор номера без поиска](https://www.figma.com/design/n9eR5MzhUA8BpvjO9ciYgi/?node-id=17511-164381)
- [14348:114250 — длинный информационный список стран без поиска](https://www.figma.com/design/n9eR5MzhUA8BpvjO9ciYgi/?node-id=14348-114250)

**Основной паттерн:** вместо системного HTML-dropdown в прототипе используется интерактивное **поле выбора → Bottom Sheet → список вариантов → обновление поля**. Селектор — **композиция** существующих `Input.mobile`, `modal` и `list.mobile`, а не новый подтверждённый Figma Component Set.

### Структура панели выбора

1. Сверху handle **56 × 4 px**, затем заголовок выбора и содержимое в горизонтальной сетке **16 px**.
2. Когда сценарий предусматривает поиск — **Input.mobile высотой 54 px** с иконкой поиска **справа**. Пример placeholder: «Найти страну».
3. Ниже — отдельный **белый контейнер** с вариантами `list.mobile`, строки **54 px**, без дополнительных промежутков между строками. Длинный список прокручивается **внутри** Bottom Sheet.
4. **Поиск не является безусловным требованием каждой модалки**: он есть у выбора страны, но отсутствует в показанных модалках выбора номера и информационного списка. Для большого каталога данных включать его, для короткого списка ориентироваться на согласованный сценарий.
5. Отсутствующие результаты должны давать понятное пустое состояние, а не пустую панель без объяснения.

### Иконки и выбранное значение

- **Справа у строки** отображается иконка категории: **страна → флаг**, **банк → логотип/иконка банка**, **сеть → иконка конкретной сети**.
- После выбора **тот же тип иконки справа** присутствует и в заполненном поле селектора; текст выбранного значения выводится внутри поля под его маленьким label.
- Не подменять логотип конкретного банка/сети случайным изображением. Если официальный ресурс недоступен, **фиксировать отсутствие ресурса**; универсальная иконка допускается только как явно обозначенная временная заглушка прототипа.
- Названия и доступность элементов, дополнительные данные (`subtitle`, код страны и т. п.) должны поступать из сценария/API или локальных тестовых данных прототипа, **не выдумываться как бизнес-правила**.

### Взаимодействие (принято для HTML-прототипов)

- Тап по селектору открывает панель; ввод в поиск фильтрует элементы.
- Тап по разрешённой строке **сохраняет её значение, закрывает панель и обновляет текст с иконкой** в исходном поле.
- Закрытие **без выбора** (нажатие вне панели, Escape, жест вниз по handle) **не должно сбрасывать прежнее значение**.
- Недоступную строку нельзя выбрать; пустой результат поиска должен быть показан текстом.
- Должны работать клавиатурная навигация, доступные имена, возврат фокуса и закрытие без потери уже введённых данных на исходном экране.

**Статус источника:** геометрия, цвета и состав Figma-узлов измерены на указанных экранах; конкретные правила фильтрации, отмены и обработки фокуса — согласованная функциональная реализация HTML-паттерна, а не доказательство всех нативных состояний Figma. Точная разметка компонентов и состояние кодового переноса: [component-map.md](./component-map.md), [shared/README.md](../shared/README.md).

## 12. Контроль качества: модалки, селекторы и инпуты

Дополнительно к разделу 7 для каждого нового прототипа:

- **Input.mobile:** проверять Enable, Enable + placeholder, Filled, Focus, Invalid, Disabled; label и value остаются внутри **одной рамки** высотой 54 px; между полями формы 12 px.
- **Modal:** стандартная панель на Secondary, список — отдельный белый блок; кнопки внутри модалки — **M**; для Primary/M проверять **44 px**, а не обычные 54 px экранной кнопки.
- **Сетка модалки:** боковые поля 16 px, handle 56×4 px, нижняя системная область и корректная прокрутка длинного содержимого.
- **Список:** не смешивать радиус 16 px списка документов и 12 px списка поискового селектора; не добавлять 12 px между соседними строками одной группы.
- **Селектор:** проверить открытие, поиск (если включён), найденные/не найденные значения, выбор, иконку справа в строке и заполненном поле, закрытие без изменения значения, disabled и длинный список.
- **Устойчивость:** проверять на ширинах **375 и 390 px**, отсутствие горизонтальной прокрутки, ошибок JS и неработающих ресурсов; не ломать возврат назад и предыдущее состояние.
- **Figma-разметка:** использовать точные исходные названия `Input.mobile`, `list.mobile`, `Button.mobile`, `modal`; составной HTML-паттерн селектора **не выдавать** за самостоятельный компонент Altyn.Base без подтверждения в библиотеке.
